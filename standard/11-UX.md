# 11 — UX

Prefixo de requisitos: `UX`

UX não é "deixar bonito depois". São regras de comportamento que fazem parte da
definição de pronto.

---

## Ações destrutivas

Nunca execute exclusão direto no clique.

```
┌─────────────────────────────────────────────┐
│  Excluir cliente João Almeida?              │
│                                             │
│  Esta ação poderá afetar:                   │
│    • 12 cotações                            │
│    • 4 emissões                             │
│    • 3 documentos                           │
│                                             │
│                    [Cancelar]  [Excluir]    │
└─────────────────────────────────────────────┘
```

A confirmação mostra **o que será afetado**, não um "tem certeza?" genérico.

Para ação crítica e irreversível, exija digitação:

```
Digite EXCLUIR para confirmar.
[________]
```

E quando a ação é reversível, prefira **desfazer** a confirmar:

```
Cliente excluído.  [Desfazer]
```

Regra: o botão destrutivo nunca é o primeiro no foco, nunca tem a cor de ação
primária, e nunca fica encostado no botão de ação frequente.

## Feedback

Toda ação do usuário tem resposta visível em até 100ms — nem que seja o estado
de carregamento.

| Duração | Tratamento |
| --- | --- |
| < 300ms | Nada especial |
| 300ms – 2s | Spinner no botão / skeleton |
| 2s – 10s | Indicador com contexto ("Gerando PDF...") |
| > 10s | Processamento assíncrono + notificação ao terminar |

Sucesso é confirmado (toast, mensagem, mudança visível de estado). Operação que
"parece que não fez nada" é a principal fonte de duplo clique e registro
duplicado.

## Mensagens

- Português claro, sem jargão técnico, sem culpa no usuário.
- Diz **o que aconteceu** e **o que fazer**.

| Ruim | Bom |
| --- | --- |
| "Erro 500" | "Não foi possível salvar. Tente novamente." |
| "Campo inválido" | "CPF inválido. Verifique os 11 dígitos." |
| "Falha na operação" | "O voo selecionado não está mais disponível. Escolha outro." |
| "Você não tem permissão" | "Você não tem permissão para aprovar emissões. Fale com um administrador." |

## Navegação

- O usuário sempre sabe onde está (título de página, breadcrumb, item ativo no menu).
- Voltar do navegador funciona; estado de filtro e paginação persiste na URL.
- URL é compartilhável: a mesma URL leva à mesma tela com os mesmos filtros.
- Sem beco sem saída: toda tela de erro, vazio ou permissão negada oferece saída.

## Formulários

- Campos na ordem que a pessoa pensa, agrupados por assunto.
- Campo obrigatório marcado; opcional também, quando a maioria é obrigatória.
- Validação de formato no `blur`; validação de negócio no envio.
- Erro não apaga o que o usuário digitou. Nunca.
- Formulário longo tem salvamento de rascunho ou é dividido em etapas com progresso.
- Botão primário à direita, cancelar à esquerda, consistente no sistema inteiro.

## Listagens

- Colunas mais importantes primeiro; ações no fim.
- Ordenação e filtro visíveis, com indicação clara do que está ativo.
- Filtro ativo é visível e removível individualmente ("Limpar filtros").
- Contagem de resultados sempre exibida.
- Paginação com controle de itens por página.
- Seleção múltipla mostra quantos foram selecionados e o que se pode fazer.

## Tempo e continuidade

- Sessão prestes a expirar avisa antes, com opção de continuar.
- Trabalho não salvo nunca se perde em silêncio.
- Processamento longo continua se o usuário fechar a aba, e ele é notificado.

## Mobile

- Alvo de toque mínimo de 44×44px.
- Tabela em telas pequenas vira cartão ou rola horizontalmente com indicação.
- Ações primárias alcançáveis com o polegar.
- Modal em mobile ocupa a tela como drawer, não como caixinha espremida.
